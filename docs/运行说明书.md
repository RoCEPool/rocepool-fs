# rocepool 运行说明书

rocepool：基于 RDMA/RoCE 的内存池分布式文件系统。原生 C 的 MDT（元数据）/OST（数据）服务端，三种客户端（C FUSE、LD_PRELOAD 拦截库、Python 参考实现），OST 可挂 NVMe 容量层（内核 O_DIRECT 或 SPDK 后端，可选 P2PDMA），全套自动化：预检、编译、部署、起服务、跑官方 IO500、出带瓶颈分析的报告。

本文只讲"怎么跑"。各轮设计与结果见 `README.md` 和 `docs/`（最新一轮：`docs/AWS_ROUND.md`）。

**最省事的入口**：解压后 `sudo ./run.sh`（有网卡跑真机，没网卡跑 10 节点模拟）；在 AWS 上用 `python3 tools/aws_cluster.py run ...`（第 4b 节）。

## 1. 目录结构

| 目录 | 内容 |
|---|---|
| `roce/native/` | C 代码：`roce_transport.c`（RDMA 传输，verbs/rdma_cm：RoCE 网卡、Soft-RoCE）、`ofi_transport.c`（同一接口的 libfabric 传输：AWS EFA）、`rocepool_servers.c`（MDT/OST 服务端）、`ost_tier.c`（OST 的 NVMe 容量层）、`rocepool_fs.c`（客户端核心）、`rocepool_fuse.c`（FUSE 客户端）、`rocepool_intercept.c`（LD_PRELOAD 拦截客户端）、`rocepool_kv.c`（原生 KV API）、`rocepool_cufile.c`（GPU 直读：cuFile 接口）、`build.sh`（真网卡编译）、`softverbs/`（RDMA 用户态模拟器，无网卡时用） |
| `roce/`, `fs/`, `storage_engine/` | Python 参考实现（协议、MDT、数据分片、POSIX 层） |
| `tools/` | 自动化：`roce_onsite.py`（真机一条命令）、`io500_run.py`（N 节点 IO500）、`bench_ior.py`（本地 IOR/mdtest）、`roce_preflight.py`（RoCE 预检）、`nvme_preflight.py`（NVMe/P2P 预检）、`io500_model.py`（瓶颈分析与投影）、`aws_cluster.py`（AWS 一条命令：开机→装环境→跑→取报告→释放）、`bench_gds.py`（GPU 检查与直读测速）、`bench_kvcache.py`（KV cache 复用与 TTFT） |
| `tests/` | 465 个测试（`python3 -m unittest discover -s tests -t .`） |
| `stress_reports/` | 历次运行报告（JSON），编号即时间顺序，最新 `39_io500_sim10_intercept.json` |
| `docs/` | 每一轮的设计文档与结果 |

## 2. 环境要求

**离线可用：** 包里的 `deps/` 带齐了第三方源码：MPICH 4.2.3、官方 IO500（含它固定版本的 IOR、pfind、lz4、schema 工具）、IOR、libfabric 2.1.0、rdma-core 59.2。IOR 已预先生成好 configure，现场不需要 autotools，也不需要访问外网，编译时自动从这里取（`tools/deps.py`）。设 `ROCEPOOL_OFFLINE=1` 则完全禁止联网下载：缺东西会直接报出缺什么，不会卡在下载上。FUSE 客户端不再依赖系统内核头文件的版本，Ubuntu 22.04（内核 5.15）上同样能编译。需要更新这些源码时，在能上网的机器上运行 `tools/make_deps.sh`。


**每台机器**（真机部署时每个节点都要满足）：

- Linux x86_64，内核 ≥ 5.x；FUSE over io_uring 需要 ≥ 6.14；P2PDMA 需要 ≥ 6.2
- root（FUSE 挂载、命名空间、RoCE 参数修正）
- `python3` ≥ 3.9，`gcc`，`make`，`git`，`cmake`（rdma-core 自动编译时用）
- 真网卡：rdma-core 开发包（`libibverbs-dev librdmacm-dev` / `rdma-core-devel`）——`build.sh` 会自己装或自己从源码编
- 跑 IO500 的机器还需要：`curl`、`autoconf automake libtool pkg-config`（MPICH 和 IOR/IO500 第一次运行时自动下载编译到 `.bench_cache/`，之后复用）
- 多机：本机能免密 ssh 到各节点（`root@host`），每台主机名互不相同，代码树放在**每台相同的绝对路径**（脚本会自动同步）

**无网卡的开发机**：以上去掉 rdma-core 即可，所有测试和模拟集群走 `softverbs` 模拟器。

## 4. 真机部署与 IO500（主路径）

**一条命令完成全部**：预检 → 编译 → 传输层验证 → 同步到各节点 → 各节点预检与编译 → 起 N 个 MDT + N 个 OST → 客户端探测 → 跑官方 IO500 → 报告 → 清理。

### 4.0 集群配置文件 cluster.conf（推荐，台数不限）

所有节点写在一个文件里，之后在其中任意一台上 `sudo ./run.sh` 一路跑完，不需要 `--peers`，也不会问密码：

```bash
cp cluster.conf.example cluster.conf     # 然后编辑
sudo ./run.sh                            # 有 cluster.conf 就按它跑；--conf 别的文件 可指定
```

```
[login]
# 各节点上一个有 sudo 权限的用户和它的密码（所有节点相同）
# 注意：password 这一行后面不要写注释，# 也算密码的一部分
user = admin
password = xxxx
[nodes]
# SSH 地址          RoCE IP            主机名（可选）
10.0.0.11       10.10.0.11      node01
10.0.0.12      10.10.0.12     node02
...                                   # 100 台就写 100 行
```

run.sh 会自动（`tools/cluster_conf.py`，32 台并行）：

1. 按 RoCE IP 认出哪一行是本机，其余都是对端；本机 RoCE IP 也自动作为 `--ip`。
2. 本机 root 到每台对端的免密登录：已经能免密的不动；不能的，用 `[login]` 的用户和密码登录**一次**，把本机 root 的公钥装进对端 root（不需要 sshpass，不需要人敲）。之后每次运行都不再用密码。
3. 主机名有重复（克隆机常见）时，按第三列改名；不重复则不改。
4. 文件含密码，自动改成仅 root 可读（600）；不会被打进程序包，也不会同步到其它节点。公钥装好后可以把密码删掉。

密码留空且节点间还不能免密时：在终端上只问一次（所有节点共用）。

### 4.1 直接用命令行参数

```bash
# 单机（网卡回环）
sudo python3 tools/roce_onsite.py --ip 192.168.50.1

# 两机
sudo python3 tools/roce_onsite.py --ip 192.168.50.1 --peer root@node2 --peer-ip 192.168.50.2

# N 机（10 节点）：--peers 列出除本机外的每一台，格式 user@host=RoCE_IP
sudo python3 tools/roce_onsite.py --ip 192.168.50.1 \
     --peers root@n2=192.168.50.2,root@n3=192.168.50.3,...,root@n10=192.168.50.10 \
     --bench full
```

参数：

| 参数 | 含义 |
|---|---|
| `--ip` | 本机 RoCE IP（不给则自动从 RoCE v2 GID 探测） |
| `--peers` | 其余节点，`user@host=ip` 逗号分隔 |
| `--bench quick\|full\|none` | `quick`（默认）：30 s stonewall 快跑；`full`：先快跑再跑一轮**原封不动的官方 300 s 正式跑**（可提交的分数）；`none`：只部署不跑 |
| `--force` | 某步 FAIL 也继续 |
| `--lib` | 跳过编译，用现成的库 |
| `--report` | 报告路径（默认 `onsite_report.json`） |

每一步输出 PASS / WARN / FAIL，默认第一个 FAIL 即停。预检会自动修正可修的（RoCE v2 模式、memlock 限制、主机名解析），不能修的会说明原因。

**产出文件**：

| 文件 | 内容 |
|---|---|
| `onsite_report.json` | 每一步的结果与细节 |
| `onsite_io500.json` | 快跑的 IO500 报告（含瓶颈分析、投影） |
| `onsite_io500_valid.json` | `--bench full` 的正式跑报告 |
| `onsite_cluster.json` | 集群描述；之后可直接 `ROCEPOOL_CLUSTER=onsite_cluster.json python3 tools/io500_run.py ...` 重跑任何配置 |
| `roce_env.sh` | 预检得出的传输参数（ToS/DSCP、busy-poll 等） |
| `.bench_cache/io500_run/` | 原始输出：`io500.out`、每个服务端的日志 `mdt<节点>_<端口>.log`/`ost<节点>_<端口>.log`、客户端日志、IO500 的 `results/` |

**运行中自动决定的事情**（不需要人工干预）：

1. **客户端**：对 FUSE 经典通道、FUSE over io_uring（内核支持时自动打开 `fuse.enable_uring`）、LD_PRELOAD 拦截库各做一次短跑，用最快的；三个结果都在报告的 `client_probe` 里，正式跑沿用快跑的选择。
2. **NVMe 层**：每节点跑 `tools/nvme_preflight.py`，有 NVMe 文件系统就把 OST 的数据写穿到那上面（每 OST 一个文件，大小按空余自动定），没有则纯内存；报告 `ost_tier` 字段记录每节点的决定。裸块设备和 SPDK **不会自动选**，见第 6 节。
3. **P2P 内存**：内核 ≥ 6.2、网卡 mlx5、盘发布了 CMB、网卡与盘在同一 root port 下时，OST 的请求缓冲区改从盘的 CMB 分配；网卡拒绝注册会自动退回主机内存并在 OST 日志打一行。

## 4b. 在 AWS 上跑

EC2 没有 RoCE 网卡，两条路，**一条命令**全包（本机需要装好并登录 `aws` CLI；要用的权限：EC2 建/删实例、安全组、密钥对、置放群组，SSM 读公共参数）：

```bash
# 路线二：EFA（AWS 自己的 RDMA 网卡，硬件 RDMA read）——libfabric 传输后端，build.sh 见到 EFA 自动选
python3 tools/aws_cluster.py run --mode efa --nodes 10 --region us-east-1

# 路线一：Soft-RoCE（rxe）——代码不改，内核把普通网卡变成 RoCE v2 设备；CPU 代替网卡干活，测的是软件
python3 tools/aws_cluster.py run --mode rxe --nodes 3 --quick

python3 tools/aws_cluster.py list                       # 还占着资源的运行
python3 tools/aws_cluster.py down --run-id rp-2026...   # 释放（--keep 或中断后用）
```

它自动做：查凭证与区域 → 选 Ubuntu 24.04 镜像、有这个机型的可用区 → 建密钥对、安全组（成员间全通，EFA 必需；SSH 只放本机公网 IP）、cluster 置放群组 → 开 N 台（efa 模式每台挂 EFA 网卡）→ **每台到 `--max-hours`（默认 6 h）自动关机即终止**，本机断了也不会一直计费 → 每台装环境（rxe：`rdma_rxe` + `rdma link add rxe0`、MTU 9001；efa：AWS EFA 安装包，含 libfabric）、节点间 root 免密 → 把代码树传到第一台，在那里 `./run.sh --peers <其余各台私网IP>`（预检、编译、传输验证、功能、基准、全节点 IO500），实时显示进度 → 报告取回 `aws_runs/<run-id>/` → 终止实例、删掉建的所有东西（`--keep` 则保留）。

| 参数 | 含义 |
|---|---|
| `--mode efa\|rxe` | 传输方式（默认 efa） |
| `--nodes` | 台数（默认 10） |
| `--type` | 机型；默认 efa `c6in.32xlarge`（128 vCPU、200 Gb、EFA 带 RDMA read）、rxe `c6in.16xlarge`。要本地 NVMe：`i4i.32xlarge`；efa 模式机型必须支持 EFA（不支持会直接拒绝，不开机） |
| `--quick` | 30 s 快跑（不加则在快跑后跑官方 300 s 正式跑） |
| `--max-hours` | 安全上限（默认 6） |
| `--keep` | 跑完不释放，打印 ssh 命令 |
| `--self-test` | 头节点上也跑单元测试 |
| `--az` / `--region` / `--ssh-cidr` / `--disk-gib` | 可用区、区域、允许 SSH 的网段、系统盘 |

已经有自己开好的 AWS 机器：EFA 机型装好 EFA 安装包后直接 `sudo ./run.sh --peers ...`（自动识别 EFA，走 libfabric 后端）；普通机型 `sudo ./run.sh --soft-roce --peers ...`（自动在每台建 rxe0）。安全组需允许成员之间全部流量。

两条路线的区别：rxe 每个 RDMA 操作都是 CPU 在做，带宽和延迟都远不如真网卡，适合验证功能和多节点流程；EFA 是真 RDMA（SRD 可靠数据报，Nitro v4 以上机型硬件 RDMA read），分数有意义。EFA 是乱序交付的，单边读的校验按乱序方式做（先读数据后读版本号），单边元数据查找在 EFA 上默认关闭（要三次往返，不如一次 RPC），`ROCEPOOL_DIRECT_LOOKUP=1` 可强开。详见 `docs/AWS_ROUND.md`。

## 4c. GPU 直读（GPUDirect Storage）

渲染、训练这类用大量 GPU 的程序，数据可以从 rocepool 直接流进显存：网卡把 OST 内存里的数据直接 RDMA 写进 GPU 显存，不经过主机内存，CPU 不碰数据（和 WEKA、DDN 的 GDS 支持一样）。接口是 NVIDIA 标准的 cuFile（`libcufile.so.0`），PyTorch/KvikIO、RAPIDS、DALI 以及用 cuFile 读数据的渲染程序都不用改代码。

```bash
# GPU 节点上（build.sh 已经编好 roce/native/cufile/libcufile.so.0）
export LD_LIBRARY_PATH=<rocepool目录>/roce/native/cufile:$LD_LIBRARY_PATH
export ROCEPOOL_MDTS=... ROCEPOOL_OSTS=...      # 和拦截库一样
export ROCEPOOL_PREFIX=/mnt/rocepool            # FUSE 挂载点（或拦截库的前缀）
python3 你的程序                                 # 它的 cuFile 读写就走 rocepool 直通显存
```

- **不用手动做任何事**：`run.sh` 里有 `gds` 一步（结果 `onsite_gds.json`，在结果包里）。它会检查每台机器的 GPU、驱动、能否把显存注册给网卡（dma-buf 需开源版内核模块；或 nvidia-peermem，缺了会自动 modprobe），以及 GPU 和网卡在 PCIe 上的远近（不同 CPU 插槽会提示）。有 GPU 的机器还会跑测速：直通显存、经主机内存中转（不支持 GDS 的存储就是这样）、所有 GPU 同时读，各给出 GB/s。
- 没有 GPU 的机器这一步显示 "no NVIDIA GPU"，不算失败。
- 显存注册不了时自动退回经主机内存中转，结果照样正确，报告里会标 WARN。
- **AI 推理的 KV cache（前缀缓存、prefill/decode 分离）**：KV API 新增直通显存的调用，适合 KV 块。Python 用法：`buf = kv.register_device(tensor.data_ptr(), 字节数)`、`kv.cached_prefix(块键列表)`（每个 OST 一次往返查出已缓存的前缀块数）、`buf.mget(...)`/`buf.mput(...)`。数据由网卡直接 RDMA 进出显存，不经主机内存，也不经元数据服务。`run.sh` 里的 `kvcache` 一步自动测：按真实模型的 KV 尺寸（快测 Llama-3-8B，缓存 4096 个 token 中的 3072 个；全测 Llama-3-70B，8192 个中的 6144 个）存入、查前缀、载入显存，逐块校验数据，给出载入延迟（p50/p99）、GB/s 和 TTFT（用缓存与全部重算对比；prefill 时间按 GPU 型号算力估算，报告里有标注）。结果在 `onsite_kvcache.json`。没有 GPU 的机器测"载入主机内存"这一档。
- 详细说明：`docs/GPUDIRECT_STORAGE.md`。

## 5. 看结果

跑完会打印一张表，`io500_report.json` 里有全部数据：

```
phase            measured   emu%  rpc/op  hot MDT   projected   bottleneck
ior-easy-write   ...        ...                                 RAM to hold a 300 s write phase / NVMe tier write bandwidth
mdtest-hard-write ...                                           per-rank latency / CPU of the busiest node / ...
projected on ...: bw X GiB/s, md Y kIOPS, score Z
score range over the estimated inputs: a .. b
vs WEKA Afton (score 105.94): ...
what the fixes are worth (cumulative): ...
```

- **measured**：这次跑出来的真实数字（真机上这就是你的分数；正式跑看 `[SCORE]` 行）。
- **bottleneck**：按实测的每操作 CPU/RPC/字节数推出的、该阶段最先撞到的上限。
- **projected**：把实测单次开销投影到目标硬件（`--project`，真机默认 `auto` = 这些主机本身）；真机上实测和投影应接近，差得远说明模型漏算了什么（表里 "model check" 一行给出比值）。
- 真机报告里 `node_facts`、`ost_tier`、`client_probe`、`fuse_channel_probe`、`dead_servers`（若有服务端死掉，附日志尾部）都值得看。

## 6. 手动控制（可选）

集群已经由 `roce_onsite.py` 建好（`onsite_cluster.json`）之后，可直接调 `io500_run.py`：

```bash
export ROCEPOOL_CLUSTER=onsite_cluster.json
sudo -E python3 tools/io500_run.py --valid                      # 正式 300 s 跑
sudo -E python3 tools/io500_run.py --client intercept --ost-tier none   # 强制拦截库 + 纯内存
sudo -E python3 tools/io500_run.py --ost-tier file:/dev/nvme1n1 # 每节点同一块裸盘（会被覆写！）
sudo -E python3 tools/io500_run.py --ost-tier spdk:0000:41:00.0 # SPDK 后端（需 SPDK_DIR 编译，见下）
```

常用参数：`--client auto|fuse|intercept`、`--direct-read auto|on|off`（单边读/单边查找，auto 在探测里对比开关）、`--bind-ranks auto|numa|core|none`、`--fuse-uring auto|on|off`、`--ost-tier auto|none|file:PATH[:GIB]|spdk:TRADDR[:NSID]`（`{n}` 代表 OST 编号）、`--ost-ram-cache-mib`、`--ranks-per-node`、`--mdts-per-node`、`--osts-per-node`、`--stonewall`、`--valid`、`--project`、`--report`。

**SPDK 后端**：在每台机器上先编译 SPDK（`git clone https://github.com/spdk/spdk && cd spdk && git submodule update --init && ./configure && make`），把目标 NVMe 绑到 vfio-pci（`scripts/setup.sh`，会让该盘脱离内核），然后 `SPDK_DIR=/path/to/spdk bash roce/native/build.sh`，再用 `--ost-tier spdk:<PCI地址>`。SPDK 路径已按 v25.05 头文件编译通过但未在硬件上跑过，第一次跑请看 OST 日志。

**只跑本地基准**（单机、两个网络命名空间或真网卡）：

```bash
sudo python3 tools/bench_ior.py --backend dist --hard                      # FUSE 客户端
sudo python3 tools/bench_ior.py --backend dist --hard --client intercept   # 拦截库
sudo python3 tools/io500_run.py --nodes 10                                 # 本机模拟 10 节点全套
```

**单独用拦截库跑任意程序**：

```bash
LD_PRELOAD=roce/native/librocepool_intercept.so ROCEPOOL_PREFIX=/mnt/rocepool \
ROCEPOOL_MDTS=h1:19901,h2:19901 ROCEPOOL_OSTS=h1:19951,h2:19951 \
mpirun -n 32 ior -a POSIX -o /mnt/rocepool/f ...
```
`/mnt/rocepool` 不需要存在，它只是个前缀；前缀之外的路径原样交给 libc。

## 7. 运行时环境变量（都有默认值，一般不用动）

| 变量 | 作用 |
|---|---|
| `ROCEPOOL_OST_TIER`, `ROCEPOOL_OST_RAM_CACHE_MIB`, `ROCEPOOL_P2PMEM` | OST 容量层、RAM 缓存、P2P 内存（`io500_run.py` 按预检自动设置） |
| `ROCEPOOL_PREFIX`, `ROCEPOOL_MDTS`, `ROCEPOOL_OSTS`, `ROCEPOOL_IO_THREADS`, `ROCEPOOL_INTERCEPT_LOG` | 拦截库 |

## 8. 常见问题

| 现象 | 处理 |
|---|---|
| 预检 FAIL：RoCE 模式/memlock | root 下预检会自动改；改不了的会打印具体 sysfs/configfs 路径 |
| 主机名相同或解析到 127.x | 脚本会自动写 `/etc/hosts` 修正；仍失败按提示手工加行 |
| "IO500 did not start in 300 s" | MPI rank 之间连不上：ssh 免密、防火墙、主机名解析 |
| 服务端死掉（`dead_servers`） | 看对应 `ost<节点>_<端口>.log`/`mdt<节点>_<端口>.log` 和报告里的 `kernel_log`（OOM 等）；内存不够看 `--mem-budget-gib` |
| 客户端 RPC 超时（`timed out waiting for completion`） | 机器严重超载时出现；`ROCEPOOL_RPC_TIMEOUT_MS` 加大 |
| OST 日志 `ibv_reg_mr refused the supplied (P2P) chunk memory` | 网卡驱动不支持 P2P 页注册，已自动退回主机内存，功能不受影响 |
| `Write phase needed ...s instead of stonewall 300s`（ior-easy INVALID） | 数据装不下 300 s：运行开头 `IOR data budget ... from the OSTs' capacity` 一行写明是哪台 OST 卡住容量。NVMe（含 LVM/RAID 上的）文件系统自动作层；没有就用本机最大的本地文件系统；裸盘不会自动写，需要时 `--ost-tier file:/dev/nvmeXnY` |
| 运行中服务端死掉 | 立即停止 IO500（不再继续跑后面的阶段），报告 `dead_servers[].kernel_log` 带那台机器的内核日志（OOM 等） |
| NVMe 层写失败 `tier full` | 层文件太小：`--ost-tier file:PATH:GIB` 指定更大 |
| AWS：`has no EFA` | 机型不支持 EFA：换 `c6in.32xlarge`/`i4i.32xlarge`/`hpc7a.96xlarge` 等，或 `--mode rxe` |
| AWS：预检 `libfabric` FAIL | EFA 安装包没装好，或安全组不允许成员间全部流量 |
| AWS：预检 `rdma_read` WARN | 机型不是 Nitro v4+：RDMA read 由 libfabric 用对端 CPU 模拟，功能正常、单边读变慢；探测会自己在单边读和 RPC 读之间选 |
| AWS：rxe 建不出来 | 内核缺 `rdma_rxe`：`apt install linux-modules-extra-$(uname -r)` |
| AWS：跑一半断了 | 机器到 `--max-hours` 自己终止；也可 `aws_cluster.py down --run-id ...` 立刻释放 |
